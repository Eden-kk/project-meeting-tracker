Implemented in this local increment
1. Import completion uses submitted mutation variables, not mutable form
   state. Changing workspace during an upload no longer misattributes the
   local registry entry or navigates into the wrong workspace. Changing
   upload/paste mode during the request preserves original source type.
2. Live audio's async voice adapter uses HTTPX AsyncClient instead of a
   blocking POST inside asyncio.to_thread. Caller cancellation propagates
   to local HTTP waiting and closes the owned client/file context.
3. A total asyncio deadline covers the POST and Modal-style 303 polling.
   HTTP failures/timeouts are not retried automatically: accepted upstream
   work could continue, and retry could duplicate expensive inference.

Environment note
The original repository tracked a node_modules symlink pointing to an
absent sibling worktree. This increment removes that tracked link so
pnpm can install local ignored dependencies. The original link is backed
up locally at .git/original-node-modules-link. The legacy .venv link is
unchanged; the fresh .venv-local environment is used for tests.

Boundaries
- Local tests use an HTTP mock transport; no remote GPU cancellation,
  latency improvement, throughput, or live deployment has been proven.
- Only the async live-chunk adapter changed; imported audio's synchronous
  dispatcher remains unchanged. Browser disconnect does not automatically
  guarantee ASGI task cancellation, nor does closing HTTP stop a remote job.
- BackgroundTasks is a fast path; the optional import_worker added below
  recovers committed received rows. Already-claimed work is not replayed.
- workspace_id is not authentication/authorization. Do not claim secure
  multi-tenancy or expose private data publicly until identity and access
  checks are implemented and tested across all object endpoints.
- Existing tests/storage_router/conftest.py truncates configured database
  tables. Never point that suite at user/deployed data; use an isolated
  disposable test database. This increment does not run that suite.

SECOND INCREMENT — durable pending imports and exclusive claims
Implemented and tested 2026-10-08:
- Committed imported artifacts in received state are the pending queue.
  A separate polling worker can recover rows if the API exits before its
  BackgroundTasks callback runs. No additional broker or schema is needed.
- The dispatcher uses conditional UPDATE WHERE status=received RETURNING
  as an exclusive claim, commits before ingestion, and returns immediately
  for a losing claim. Two workers cannot start inference for the same row.
- num/min/max speaker hints are persisted in meeting_sources metadata in
  the original transaction and restored by the worker.
- Final segment insertion and ready states retain one transaction; an
  insertion failure rolls back partial output before marking failure.
- Deleted, live, unsupported, in-flight and terminal records are excluded
  from recovery. Failed/in-flight records are never automatically reset.
- Fixed pre-existing clean-install migration failure: revision 0023 exceeds
  Alembic's default VARCHAR(32). Widen version_num before recording it,
  preserving existing revision names and deployed revision history.

Operator usage (only against a configured development environment):
  .venv-local/bin/python -m storage_router.import_worker --once
  .venv-local/bin/python -m storage_router.import_worker --poll-seconds 5
Worker and API need identical DATABASE_URL, INGEST_BACKEND and blob mount.
The worker is not automatically started by the API and was not deployed.
One worker processes a bounded batch sequentially; batch count reports
candidates, not successful completions. A supervisor is needed for uptime.

Fresh database verification:
- PostgreSQL 16.15, temporary local cluster, not existing application data.
- 14 integration cases passed on real PostgreSQL; one starts from the full

  simultaneous claims, missed scheduling, speaker hint recovery, failed
  ingest, simulated termination after claim, segment rollback, deleted/live

- 5 offline async transport tests passed (19 Python tests total).
- 9 ImportPage/ProcessingPage tests passed; TypeScript/Vite build passed.
- Independent read-only review checked exclusive claims and fixture safety.

Reproduce database tests with an explicitly disposable local database:
  MEETING_TEST_DATABASE_URL=postgresql+psycopg://USER@127.0.0.1:PORT/meeting_hardening_test \
    .venv-local/bin/python -m pytest tests/integration tests/unit -q
Each test creates and drops only its own random test_<uuid> schema. The
fixture rejects non-local hosts, alternate DB names, drivers and URL query
overrides; it does not import the old truncating fixture. Without this env
variable integration tests SKIP, which is not a passing DB verification.

Remaining limits / next work:
- A crash after claim is ambiguous: records stay parsing/transcribing/
  normalizing for operator investigation. This is NOT general crash retry,
  exactly-once remote inference, a lease-based queue, or high availability.
- Uploaded audio must survive API restart and be readable by the worker;
  LocalFsBlobStore does not provide cross-host durability.
- Auto-finalize has a separate crash window after transcript ready commit;
  no automatic LLM re-execution was added.
- No manual attempt history, retry/cancel UI, upstream abort or identity/
  membership authorization is implemented in this increment.
- Existing delete/ingest races are not solved by filtering already-deleted
  records. Do not generalize the claim mechanism into attempt reassignment
  without fencing tokens and conditional completion/failure writes.
